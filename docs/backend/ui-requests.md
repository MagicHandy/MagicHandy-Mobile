# Requests for the UI owner

| Surface | Requested integration | Contract or reason | UI status (2026-11-20) |
|---|---|---|---|
| Chat model | Offer an optional local connection for retrying a hosted refusal. Show the current selection and allow clearing it. | `ModelsState.refusalFallback` and `MagicHandyCore.setRefusalFallback`. The default is Off. A pending fallback loses authority when the selection is cleared. | Done (board V-RefusalFallback). The Chat model sheet shows "If <model> refuses" when the chat model runs online, and its page offers Off or a server on the local network. |
| Memory | Show the stored entries in the review sheet and retain the existing clear action. | `SessionSettings.memories` defaults to an empty list and contains the active persona's entries, newest first. Extraction is opt-in. | Done. The Memory sheet lists the saved details below the count and Clear. |
| Devices and App settings | Show the notification warning on denial and link to Android settings. Show unrestricted battery access from the system snapshot. | Read `hasSystemAccessSnapshot` before interpreting `notificationsAllowed` and `isBatteryUnrestricted`. Android owns permission prompts. | Done. Both screens, and the device pages, read the snapshot. The warning appears only once notifications were refused, or on Android 12, where nothing asks. |
| Intiface | On explicit user request, list eligible vibrators at the entered address. If the bridge has several, send the chosen index when saving. | `intifaceVibrators(address)` is read-only. `AddIntiface.deviceIndex` defaults to null for a bridge with a single eligible device. | Done (board V-AddVibrator). Setup finds the vibrators at the address first, then connects the one picked; a bridge with one vibrator has it picked already. |
| Coyote | Let the person set A and B ceilings while disconnected after acknowledging the safety notes. Provide explicit channel step buttons while running. | `setCoyoteLimits`, `stepCoyote`, `CoyoteChannel`. The default ceilings are zero. | Done (boards V-CoyotePage and V-CoyoteLive). The Coyote's page sets the limits in steps of 5 while it's disconnected. Live steps each channel by 1 up to its limit while it plays, and waits for the first report and while paused. |
| Handy | Tell the person a mounting edit takes effect at the next Start or Resume. | `SetReversed` preserves the mapping of the buffered stream. | Done, in the Reverse direction row's description. |
| Notification navigation | An optional initial Live route on `MagicHandyRoot` would let a notification use the normal navigation stack. | The platform currently mounts the existing Live screen, sheets and Stop receipt in the shared activity. | Done. `MagicHandyRoot(openLive = …)` opens Live above Chat on the normal back stack, and the platform's separate `NotificationEntry` is gone. |
| Debug settings | An optional debug-only simulation selector can be added if the owner wants to switch backends at runtime. | Debug currently always uses simulated devices and model clients. | Not planned unless the owner asks for it. |

The two additional `StopSource` entries are `ModelReply` and `CheckInTimeout`. Check any future exhaustive consumer. The current UI builds and passes its boundary tests.

Forms still close on dispatch. Per-intent completion and the motor-test duration remain owner decisions. The duration is 1.5 seconds. No form-result contract was added.
