# Port deviations

**Startup Stop evidence.** At `1b80d72e`, `internal/motion/startup.go` and its `stopTransportForStartup` helper treat the absence of a transport error as success even when the command result reports failure. Mobile requires an acknowledged halt before reading calibration or sending a positioning command. `StartupReconciliationTest` exercises an unsuccessful Stop and a Stop during positioning. Desktop should also check the result.

The comparisons below use alpha.89 at `1b80d72e`. Existing M0 safety decisions and their regression tests are recorded in the [review handoff](status.md#review-fixes-2026-11-19).

The alpha.89 refresh preserves every existing fixture payload. The 27 original-Creative atlas comparisons are inert regression inputs. They do not introduce a selectable legacy mode. The sampler's original 21 cases belong to another atlas, as the desktop review command and [parity map](../../PARITY.md) show.

The M0 receipt regression previously expected a confirmed routine Pause to return to Idle. M1 deliberately changes that assertion to Paused. Its bridge-only branch still expects Idle with `Unconfirmed(BridgeOnly)` and zero explicit presses. This is a change to an integration test, with all exported desktop expectations preserved.

Android has no desktop equivalent for a GATT callback that arrives after a platform operation's deadline. `GattQueueTest` checks priority Stop, cancellation of unsent work and retirement of a stalled generation. A late callback cannot confirm a later operation. `StorageTest` also checks that a duplicate entry ID belongs to the same chat and payload before treating it as a successful retry. These are Android adapter guarantees.

Original alpha.89 expectations were preserved. Added fixtures cover three Layered scores and six seeded tempo routines. The managed-history captures describe reference admission, while named connections are the mobile setup path.
