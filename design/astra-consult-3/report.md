# MagicHandy Mobile · First-run setup and personas

**Make skipping work all the way to Chat.** Someone who completes the adult acknowledgement and Stop rehearsal should be able to skip the model, leave MagicHandy at Utility, and finish setup. On the last screen, “No model chosen” and “Finish setup” tell that person exactly where they stand. The next most important fix is in both persona editors. “Read before every reply” tells people their description is active even at Utility, where it is omitted from the request.

The owner has already revised two earlier decisions. Four-step setup supersedes the one-page first run, and editable MagicHandy plus custom personas supersede the presets-only scope. These recommendations require no further reversals. Step 1 remains compulsory, permissions stay at the feature that needs them, and Settings still opens the compact sheet from the bottom row. The five persona fields are sufficient. Portraits, lore and import/export stay outside v1. ## Enhancement decisions

S means copy, layout or reuse of an existing control. M means a change across screens, state handling or localization. L means a new subsystem or a substantially larger test surface. **Adopt** identifies a concrete gain. **Consider** marks a preference or trade-off. **Skip** identifies work whose benefit does not justify its cost here.

**What leaves the phone.** Chats, settings and optional memory are stored locally. A normal chat request sends the context needed for that reply to the selected provider. Choosing Off cancels a pending retry. A persona level describes permitted wording. The provider can still refuse. **Creating a persona.** New persona opens the custom editor with focus on the inline name, Utility and Neutral selected, and a blank description. Short is a proposed starting length. Save adds the new entry and leaves the current speaker selected. A duplicate follows the same save flow with its settings filled in. On a dirty editor, resolve unsaved changes before duplicating the saved version. Cancelling either new draft leaves the roster intact.

**Keep reaction style about dialogue.** Use these six explanations in the picker. Neutral — “No added reaction style.” Playful — “Teases lightly and starts things.” Tender — “Attentive, reassuring and unhurried.” Teasing — “Withholds and draws things out.” Dominant — “Leads the conversation and says what happens next.” Submissive — “Follows, asks and defers.” A safe comparison for the example disclosure uses the same ordinary cue, “I have a minute.” Playful could say “A whole minute? I’ll take it. What’s on your mind?” Tender could say “I’m here. Take your time.” Display only the selected example. Opening it creates no chat turn, memory or motion.

**Keep the five fields honest.** Explicitness and reaction style select fixed instructions owned by the code. Neutral contributes zero bytes, exactly as if style were absent. Quote the free-text description as data at Warm, Intimate and Explicit. At Utility, omit it and any anatomy wording. Anatomy wording is not a persona field. The style instruction itself must contain no references to motion, speed, devices or JSON. The UI can explain the boundary once. Persona settings change neither speed limits, stroke range, allowed model controls, Autopilot nor Stop. Memory remains opt-in, with each persona's memory separate. ## Changes I would make first

1. **Close the skip path.** Give step 3 a visible Skip. Let someone with no model finish step 4, enter Chat and choose a provider later beside their draft.
2. **Keep Stop reachable through the entire flow.** Use the shared footer above the keyboard and outside every sheet or confirmation. Drop the duplicate Stop summary and its delivery guarantee.
3. **Protect the first wording choice.** Start at Utility, show all four definitions, and tell authors exactly when their saved description is used.
